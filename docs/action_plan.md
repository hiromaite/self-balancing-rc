# action_plan

## 目的
直近で「安全に動く初号機」へ最短到達するための実行計画を、優先度・依存関係・完了条件つきで整理する。

## 全体方針
1. **安全を先に固定**（電源/停止条件/復帰条件）
2. **可観測性を先に確保**（ログと試験手順）
3. **段階的に制御を高度化**（PD -> 速度制御 -> UDP）
4. **新機能は必ず受入条件を満たしてから次へ進む**

---

## Phase A: 設計確定（1〜2日）

### A-1. 要件/境界条件の確定
- 子どもモード上限（PWM/速度/旋回）を暫定値で固定
- 低電圧しきい値（警告/停止/ラッチ）を固定
- 転倒判定角・通信断タイムアウトを固定

**完了条件 (DoD)**
- `docs/requirements.md` と `docs/safety_test_plan.md` に数値が入っている
- `docs/open_questions.md` の「安全閾値系」が解消されている

### A-2. BOMと配線方針の凍結
- 34:1/47:1の選定ルール（初号機は安全寄りなら47:1）
- コネクタ規格・線径・ヒューズ容量を確定

**DoD**
- `docs/bom.md` の未確定が最小化
- `docs/wiring.md` / `docs/power_design.md` が部材レベルまで参照可能

---

## Phase B: firmware雛形（2〜3日）

### B-1. PlatformIOプロジェクト作成
- `firmware/` にPIO初期化
- `SAFE_BOOT` で必ず起動
- Serial JSON Linesで心拍ログを出す

### B-2. 安全状態機械の実装
- `SAFE_BOOT -> CALIBRATING -> ARMED_READY -> BALANCING -> FAULT_LATCHED`
- `FAULT_LATCHED` からは明示操作でのみ復帰

### B-3. コマンド/テレメトリ最小実装
- `command_seq`, `host_ts_ms`, `device_ts_ms`, `ttl_ms` を実装
- TTL切れは破棄

**DoD**
- モーター未接続で安全状態遷移ログが確認できる
- 異常コマンドで `FAULT_LATCHED` に入ることを確認

---

## Phase C: 単体試験（3〜5日）

### C-1. IMU単体
- BNO086読取（初期）
- ICM-42688-P読取（比較）
- 静止ノイズ/遅延をログ化

### C-2. モーター/エンコーダ単体
- 浮かせた状態でPWM/DIR確認
- エンコーダ方向一致確認

### C-3. 電源/保護系
- 電圧監視
- 低電圧警告/停止
- 通信断停止

**DoD**
- `docs/safety_test_plan.md` の単体試験項目が再現可能
- テストログが `docs/tuning_log.md` 形式で残っている

---

## Phase D: 倒立成立（3〜7日）

### D-1. PD制御で短時間自立
- Ki=0固定で開始
- 1秒 -> 3秒 -> 10秒を目標に反復

### D-2. 速度/旋回の外側ループ
- 低速前後進
- その場旋回
- 子どもモード制限の有効化

**DoD**
- 転倒時に確実停止
- 通信断/低電圧で停止
- 10秒自立を再現可能

---

## Phase E: 操作拡張（2〜4日）

### E-1. USBシリアル運用の確立
- `serial_monitor.py` でログ保存
- `pid_tuner.py` でパラメータ更新

### E-2. UDP運用
- コマンド受信/テレメトリ返送
- TTL/連番による古い指令破棄

### E-3. PS5中継（必要時）
- PC/RPiブリッジから `vx/wz` 送信
- デッドマン/緊急停止

**DoD**
- 低速走行を安全モードで継続可能
- 緊急停止の一発動作が確認できる

---

## 進行管理ルール
- 1機能ごとに「実装 -> 試験 -> ログ -> 振り返り」を必須化
- 不具合は「再現条件」「ログ」「暫定回避策」をセットで記録
- 新規機能は安全要件に影響する場合のみ先にレビュー

## リスクと先回り
- **リスク:** IMU遅延や取り付け剛性不足で制御が不安定
  - **対策:** IMU固定方法を先に標準化、比較ログを必須化
- **リスク:** 電源ノイズで誤動作
  - **対策:** 配線分離、コンデンサ配置、Brownoutログ
- **リスク:** 調整が感覚依存になる
  - **対策:** テンプレ化した `tuning_log` 記録を徹底
